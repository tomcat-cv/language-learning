# Hibi English

面向手机浏览器的英语沟通训练个人试用版。与现有日语应用独立，无运行依赖。

## 当前闭环

选择固定任务 → 逐轮语音或文字对话 → 按原话证据获得反馈 → 带着反馈换条件重练 → 换生活/工作情境验证 → 保存练习手记。

- 3 组固定原创试用任务，每组 3 个情境；当前不临时生成课程结构。
- 点击开始/结束录音，最多 60 秒；试听后转写，用户确认/修正后再发送。
- 支持运行时探测 MP4/WebM/Ogg 录音格式；权限拒绝、录音失败、后台中断和服务错误均有降级。
- 语音与文字输入、字幕/句型辅助分开记录。
- 评价引用必须出现在用户原话中，否则降级为待确认；不因一次练习发放能力证书。
- 任务、评分规则、模型与评价时间保留版本信息。
- 会话经服务端 HMAC 签名并绑定当前用户，24 小时内可从设备记录恢复。
- 手记和未完成对话保存在当前浏览器，按用户隔离存储键，不跨设备同步；最多 40 条反馈。
- 应用不长期保存录音。录音在页面内临时保留，用于试听及发送给配置的转写服务；文字对话及评估证据留在设备记录中。模型厂商的数据保留政策须由部署者另外确认。
- Web manifest 支持添加到主屏幕；无 Service Worker，AI 功能需联网。

## 本地运行

开发基线固定为 Node.js **24.12.0**，以 `.nvmrc` 为准，本地与 Linux CI 使用同一版本。当前没有第三方运行依赖；仍使用锁文件和 `npm ci`，方便以后可重复地安装依赖。

```sh
nvm install
nvm use
npm ci
npm run check
cp .env.example .env
# 编辑 .env，填写实际服务商支持的模型、密钥和随机签名密钥
npm start
```

打开 http://127.0.0.1:3400。源码修改后停止并重新运行。PORT 可覆盖端口。

不配置 AI 也可浏览任务和设置；开始对话会明确不可用，不会自动回退成假对话、假转写或假评价。

## 服务端配置

| 环境变量 | 含义 |
| --- | --- |
| OPENAI_API_KEY | OpenAI 或兼容服务的 API 密钥 |
| AI_BASE_URL | HTTPS 的 OpenAI 兼容 `/v1` 地址；默认 `https://api.openai.com/v1` |
| CHAT_MODEL | 支持 Chat Completions 严格 JSON Schema 输出的模型 ID，必填 |
| TRANSCRIBE_MODEL | 支持 `/audio/transcriptions` 的模型 ID，语音输入需要 |
| TTS_MODEL | 支持 `/audio/speech` 的模型 ID；可不填，届时尝试设备合成朗读 |
| TTS_VOICE | 服务商支持的语音，默认 alloy，可覆盖 |
| SESSION_SECRET | 至少 32 字符的独立随机值，用于签名会话；变更会使旧会话失效 |

模型名称不会猜测或静默选择。兼容服务还必须实际支持严格结构化输出和相应音频接口；仅仅提供同名接口不保证兼容。API Key 从不写入浏览器或会话令牌。

生成签名密钥：

```sh
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

## 部署

### Sites（已提供私有部署配置）

`.openai/hosting.json` 保存 Site 身份。运行时配置通过 Sites 的环境变量管理设置，不写进该文件。源码用 `npm run build` 生成标准 Worker ESM，部署时使用当前 Site 的源码与版本工作流。保持 owner-private 访问边界。

生产 API 依赖 Sites 验证后的 `oai-authenticated-user-id`。任何持有有效身份的私有站点用户才可请求 AI。不要将这个应用直接作为无鉴权的公网服务。

### 其他服务器

`scripts/dev.mjs` 是 loopback 开发/个人诊断服务器，会注入固定 local-owner 身份。**不能直接作为公网多用户认证后端。** 如果改为自托管，需要在服务端实现真实身份校验，再传入可信用户身份，并在 HTTPS 反向代理后运行；不可相信浏览器自行传入的身份头。

手机远程录音要求 HTTPS，手机访问电脑的普通 HTTP 局域网地址通常不能录音。局域网纯 HTTP 只能检查页面与文字流程。Sites 生产链接提供 HTTPS。

## 源码结构

- `src/tasks.mjs`：任务、情境、约束和评分维度；场景是虚构练习，不提供现实办事或专业建议。
- `src/api.mjs`：会话签名、身份边界、转写、对话、评价、重练和迁移接口。
- `src/index.html`、`styles.css`、`app.js`：手机优先界面、录音与设备记录。
- `scripts/assemble.mjs`：把模块与页面确定性组合成单文件 Worker。
- `worker/index.js`：由 assemble 生成；不要直接编辑。
- `scripts/dev.mjs`：Node 本地运行适配。
- `tests/`：接口、状态机和浏览器测试；替身模型仅存在于 tests 中，生产没有 mock 开关。

## 验证

```sh
npm run check
```

统一检查依次执行 Node 版本检查、`npm test`、`npm run build` 和 `npm run validate`，任一步失败立即停止。不需要 `.env` 或真实模型密钥。

接口测试使用注入的模型替身，不消耗真实额度，验证状态转换、身份隔离、防篡改、引用校验、错误处理和音频请求格式。

浏览器测试另用 `npm run test:browser`，不包含在 `check` 或 CI 内。目前仍需自行准备可由 Node 解析的 Playwright 以及 Chrome/对应引擎；分别启动未配置 AI 的本地开发服务器（3400）和 `node tests/fixture-server.mjs`（3401），再运行浏览器测试。不要加载真实 `.env`，也不要继承真实 AI 配置；未配置页面是测试断言的一部分。浏览器报告、截图写入忽略的 `outputs/qa`。报告可能记录不可用引擎为 skipped，应明确说明实际覆盖范围。

## 日常开发与 Linux CI

1. 阅读 `AGENTS.md`，检查工作区，从英语应用 `english-mvp` 创建功能分支，例如 `codex/voice-retry`。日语应用在独立的 `main`，不要将英语根目录合并过去。
2. 使用 `.nvmrc` 指定的 Node，运行 `npm ci`，在本地修改源码并体验功能。
3. 运行 `npm run check`。页面或录音改动另做浏览器测试；真实语音和评价质量另做实机/真实服务验收。
4. 提交源码和同步生成的 `worker/index.js`，PR 目标设为 `english-mvp`。
5. GitHub Actions 在 Ubuntu 24.04 上运行相同检查，并检查 Worker 是否与源码一致。通过之后才进入后续发布流程。

工作流为 `.github/workflows/ci.yml`：推送到 `english-mvp` 或 `codex/**`、向 `english-mvp` 提交 PR 时自动运行，并声明了手动触发入口（GitHub 是否显示该入口取决于默认分支是否包含工作流）。它不部署站点，也不使用生产密钥。配置提交并推送后才会在 GitHub 实际执行；是否强制合并前通过检查由仓库分支规则单独控制。

升级 Node 时，同时更新 `.nvmrc`、`package.json` 的 engines、锁文件和本文说明，并重新运行完整检查。当前固定版本是本机验证基线，不代表永远保持该补丁版本；应定期评估安全更新。

## 当前边界与下一步

- 已实现可配置的闭环；交付时尚无真实模型密钥，真实服务、转写准确率、延迟、成本和评价质量均需配置后验收。
- 移动视口自动化不等于 iPhone 实机验收。需要在真实 Safari 中验证首次权限、播放限制、电话/锁屏中断、蓝牙耳机和长会话。
- 当前任务和评分规则是待教学审核的试用内容。评价器只校验引用真实存在，不等于证明其语义判断正确；上线给他人学习前应建立教师标注样例集，测一致性与误判。
- 评价只覆盖对话中呈现的信息与任务表现，不评定发音、听力等级或长期掌握。
- 浏览器存储不保证长期留存。没有账号同步、服务器学习数据库或自动备份；清站点数据会删除当前设备记录。
- 无分布式请求去重或全局限额。当前 30 次/分钟是单 Worker 实例内的辅助限流，不是费用上限；同一有效会话可以重放请求。个人私有试用时应另设服务商预算上限。外部测试前应引入数据库幂等键和按用户的持久化配额。
- 下一阶段优先：真实服务验收 → 小规模教师校准 → iPhone 实机验收 → 账号与持久化 → 再考虑 iOS 客户端。
- iOS 可以复用任务和业务接口设计，但仍需增加适合原生客户端的身份认证与同步协议，并重新实现原生录音和播放；当前并未声称网页可以直接转换成完整 iOS 应用。
