# language-learning · English application

## Scope and context

- Read README.md, PROJECT.md and HANDOFF.md before making changes.
- This checkout is the English application, based on `english-mvp`. The repository's `main` branch contains a separate Japanese application. Do not merge the English root into `main`, replace Japanese files, or force-push histories.
- For feature work, branch from the English application; use `codex/<short-name>` for new branches. Target `english-mvp` when opening a pull request.
- Inspect `git status` first. Preserve unrelated user changes and local reports.

## Environment and commands

- Use the exact Node.js version in `.nvmrc`: `nvm install && nvm use`.
- Run `npm ci` after checkout. Commit package-lock.json when dependencies change; runtime dependencies are currently empty.
- `npm run dev`: local server on http://127.0.0.1:3400.
- `npm run check`: Node version consistency, API tests, build, artifact validation. Run it before handing off code changes.
- `npm run test:browser`: existing optional browser suite. Read README.md for Playwright and the two required servers. This suite is not included in `check` or Linux CI; report skipped or unexecuted browser checks explicitly.
- Do not call paid model APIs as part of the default checks. Test doubles belong only in tests.

## Source and generated files

- Edit `src/` and the relevant scripts. `worker/index.js` is generated by `scripts/assemble.mjs`; do not edit it directly.
- When source changes affect the Worker, run `npm run build` and include the regenerated tracked Worker in the change. CI rejects stale generated code.
- `dist/`, `outputs/`, `work/` and node_modules are local/generated directories, not source deliverables.
- Keep changes focused; do not reformat unrelated source files.

## Application boundaries

- `scripts/dev.mjs` injects a fixed local-owner identity. It is a development adapter, not a public production server.
- Preserve verified user identity, signed-session isolation, evidence checks and explicit unconfigured/error states. Never turn a failed real model call into fake learning feedback.
- Do not commit or log real API keys, `.env` files, session tokens, recordings or production learning records. `.env.example` contains placeholders only.
- Changes to authentication, signed state, transcription or evaluation require relevant API regression checks. UI/recording changes also require browser verification; disclose any unavailable browser or device checks.
- Real model quality, cost and latency require separate validation. Browser automation does not replace iPhone Safari microphone and interruption testing.

## Completion

- Report what changed, what checks passed and what remains unverified.
- Keep README.md commands and HANDOFF.md current when development workflow changes.
- Development CI does not deploy, configure production, or prove real AI-provider availability.
